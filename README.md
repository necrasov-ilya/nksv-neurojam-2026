# Основа для 72-часового геймджема

Запускаемый технический стенд для браузерной 3D-игры на **Godot 4.7.2, GDScript и Compatibility renderer**. Здесь нет сюжета, готовой механики, уровней и графики под неизвестную тему. Серые примитивы, тестовый звук и панель нужны только для проверки систем. После объявления темы их можно заменить или удалить.

## Быстрый запуск

1. Установите [Godot 4.7.2 Standard](https://godotengine.org/download/archive/4.7.2-stable/). Вариант .NET не нужен.
2. Откройте `project.godot` в редакторе и нажмите **F6** или **F5**.
3. Нажмите кнопку запуска. `WASD` или стрелки двигают камеру, `Q/E` поворачивают, колесо меняет масштаб, пробел показывает работу пула объектов и звука, `Esc` ставит на паузу. Кнопка нового зерна создаёт воспроизводимую раскладку тестовых маркеров.
4. Для браузера установите экспортные шаблоны той же версии Godot, выберите **Project → Export → Web**, экспортируйте в `build/web/index.html` и запустите файлы через локальный сервер. Не открывайте `index.html` напрямую с диска.

Из командной строки после установки Godot:

```bash
godot --headless --path . --editor --import --quit
godot --headless --path . --quit-after 5
mkdir -p build/web
godot --headless --path . --export-release Web build/web/index.html
python3 -m http.server 8000 -d build/web
```

Адрес проверки: `http://localhost:8000`. Если команда `godot` отсутствует, укажите путь к исполняемому файлу внутри приложения Godot. Веб-экспорт проверяйте в тех браузерах и на тех устройствах, на которых судьи откроют игру.

## Что уже работает

| Узел | Файл | Назначение |
| --- | --- | --- |
| Состояния | `scripts/core/session_state.gd` | Готово, игра, пауза. Сигнал обновляет интерфейс. |
| Ввод | `scripts/core/input_manager.gd` | Одно место для клавиш и действий. |
| Камера | `scripts/core/camera_manager.gd` | Перемещение, поворот и масштаб. |
| Звук | `scripts/core/audio_manager.gd` | Воспроизведение, музыка, отключение звука. |
| Мир | `scripts/core/world_manager.gd` | Нейтральный стенд из примитивов. |
| Генерация | `scripts/core/procedural_layout.gd` | Раскладка по числовому зерну с повторяемым результатом. |
| Пул | `scripts/core/object_pool.gd` | Повторное использование экземпляров вместо постоянного создания. |
| Интерфейс | `scripts/ui/debug_hud.gd` | Кнопки проверки систем. |

`scenes/main.tscn` связывает узлы. `scenes/debug_pulse.tscn` и `assets/audio/test_click.wav` демонстрируют пул и звук. Ресурсы игры после объявления темы складывайте в `assets/models`, `assets/textures`, `assets/audio`, а игровые сцены и сценарии выделяйте в `scenes/game` и `scripts/game`. Держите технические модули отдельно от игрового содержания.

## Выбор стека

Godot 4.7.2 выбран для быстрой сборки игры одним человеком. Сцены, анимация, интерфейс, физика, импорт моделей и экспорт уже встроены в редактор. Для веб-версии используйте **GDScript**, режим **Compatibility** и однопоточный экспорт. Godot 4 Web требует WebGL 2.0. Эффекты звуковой шины в стандартном браузерном режиме воспроизведения имеют ограничения. Проверяйте эффекты и микс в самом веб-экспорте.

Three.js имеет смысл выбрать вместо Godot, если после объявления темы игра окажется небольшой интерактивной 3D-страницей, а важнее минимальный размер загрузки и тесная интеграция с браузерным интерфейсом. Не меняйте движок посреди джема только ради визуального стиля.

## До старта и после темы

До 9 октября тренируйте только процесс: импорт тестовой модели, звук, запуск, экспорт и проверку в браузере. Письменно уточните у организатора, можно ли переносить готовый технический шаблон в проект джема. Формулировка про сборку игры с нуля сама по себе не даёт надёжного ответа на этот вопрос. Если использование основы не разрешат, создайте чистый проект 9 октября и повторите уже отработанные действия.

Практические инструкции: [конвейеры ресурсов](docs/PIPELINES.md), [работа с агентами](AGENTS.md), [проверка готовности и план 72 часов](docs/JAM_PLAN.md).

## Репозиторий и сборка

Проект хранится в локальном Git. `.godot/` и `build/` не фиксируются, исходники, `export_presets.cfg` и аудиофайл фиксируются. Проверка GitHub Actions в `.github/workflows/check.yml` запускает импорт и короткий старт при каждом отправленном изменении. Для публикации понадобится ваш удалённый репозиторий и выбранная площадка. Сам веб-экспорт делайте после установки экспортных шаблонов и проверяйте его локально перед загрузкой.

Во время джема фиксируйте изменения после каждого рабочего среза: `идея`, `первый цикл`, `графика`, `звук`, `сборка`. Держите рабочую игру на основной ветке, экспериментальные задачи агентам давайте в отдельных ветках или рабочих копиях.
