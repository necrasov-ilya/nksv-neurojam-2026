# Конвейеры ресурсов

Конвейеры проекта LATENTPUNK после объявления темы. Правила сдачи — [JAM_PLAN.md](JAM_PLAN.md), концепт — [CONCEPT.md](CONCEPT.md), происхождение и команды запуска миров — [SOURCES.md](SOURCES.md).

## Blender → Godot → браузер

1. Делайте исходник `.blend` вне папки игрового экспорта или в `source_art/`. Сохраняйте один логический объект в одном файле. Оставляйте понятные имена объектов и материалов.
2. Перед экспортом проверьте масштаб, примените нужные преобразования, удалите невидимую геометрию. Нужные текстуры сохраните отдельными файлами. Для обычных материалов используйте Principled BSDF и проверяйте UV.
3. В Blender выберите **File → Export → glTF 2.0** и **glTF Binary (.glb)**. Экспортируйте выбранные объекты. Анимации включайте только если они нужны. Выход поместите в `assets/models/`.
4. Дождитесь импорта Godot. Перетащите `.glb` на сцену, проверьте масштаб, ориентацию, материалы и анимации. Для игровых коллизий и логики создавайте наследуемую сцену, не правьте импортированный ресурс напрямую.
5. Сразу соберите веб-экспорт и проверьте тот же объект в браузере. Если вид отличается, сначала проверяйте материалы, прозрачность, освещение и режим Compatibility.

Для повторяющихся объектов используйте `MultiMesh`, как в `world_manager.gd`. У каждого экземпляра MultiMesh нет отдельной автоматической отсечки по области видимости, поэтому разбивайте большие поля на участки и измеряйте производительность.

## Звуки и музыка

1. После объявления темы составьте короткий список звуков, привязанный к действиям игрока: действие, отклик, ошибка, завершение. В начале достаточно 3–5 эффектов.
2. Для генератора звука пишите запрос по форме: **источник → действие → характер → длительность → фон**. Пример без темы: `один короткий сухой щелчок, 0.2 секунды, без речи, музыки и фонового шума`.
3. Сохраняйте оригиналы отдельно. Обрежьте тишину, уберите щелчки на границе, выровняйте громкость, прослушайте вместе. Для коротких эффектов обычно удобен WAV или Ogg, для длинной музыки Ogg. Сравнивайте размер и задержку в браузере.
4. Если установлен FFmpeg, базовая подготовка одного эффекта выглядит так:

```bash
ffmpeg -i source.wav -af "highpass=f=60,loudnorm=I=-18:TP=-1.5:LRA=8" -ar 48000 -ac 1 assets/audio/action.wav
```

Настройки громкости затем подгоняйте на слух в общем миксе. Для бесшовной музыки проверьте начало и конец на слух, а не полагайтесь только на формат файла. В браузере запускайте музыку после действия пользователя. У Godot Web в стандартном режиме сэмплов есть ограничения звуковых эффектов шины, реверберации и процедурного звука, поэтому нужные обработки лучше подготовить в файле и проверить экспорт.

## Текстуры и иконки

Сначала выберите ограниченную палитру, одну форму силуэта и один принцип освещения. Генератору изображений задавайте конкретный тип ресурса: `бесшовная базовая текстура материала` или `одна иконка на прозрачном фоне`. Для текстур добавляйте требования к повторяемости и отсутствию теней/перспективы. Для иконок задавайте размер, чистый силуэт и прозрачный фон. Проверяйте реальные края и прозрачность после генерации.

Нормали и шероховатость делайте в Blender или редакторе текстур и проверяйте под игровым светом. Не считайте автоматически сгенерированные карты физически согласованными. Сохраняйте исходники и отмечайте инструмент, дату, запрос и условия использования ресурса в `assets/SOURCES.md` после того, как начнёте создавать реальные материалы.

## Бюджет качества для одного участника

Начните с одного читаемого ракурса, одной палитры, понятного света и выразительного отклика на действие. Сначала соберите вертикальный срез из примитивов. Модели, текстуры и звуки добавляйте лишь тогда, когда они усиливают уже работающий цикл игры. Проверяйте FPS и размер загрузки в браузере после каждой крупной партии ресурсов.


## Браузерные миры → проверка → интеграция

1. Хранить каждый модуль в `games/<upstream-slug>/`, сохраняя точное название и тип поставки в `SOURCES.md`. Для исходного проекта переносить HTML/JS/TS, ресурсы, манифест, lock-файл, конфигурацию и лицензии. Для готовой игры — entry HTML, все JS/CSS chunks, runtime-ресурсы и notices.
2. Не переносить `.git/`, `node_modules/` и кэши. Локально сгенерированные `dist/build` не коммитить; **опубликованные upstream-сборки допускаются** по решению участника. Уже перенесённые исходники сохранять. `.gdignore` в `games/` исключает независимые веб-проекты из импорта Godot; это не интеграция.
3. Сравнить пути и хеши перенесённых файлов с upstream. Записать коммит и отдельно добавленные лицензии. Минифицированный Vite bundle допустим как готовая игра, но не называется оригинальным исходным проектом.
4. Для проектов с lock-файлом использовать `npm ci`; single-file HTML и готовые сборки запускать локальным HTTP-сервером без повторной сборки. Точные команды и сетевые зависимости — в `SOURCES.md`. Не добавлять зависимости оболочки до выбора архитектуры.
5. После импорта собрать только исходные проекты существующими командами и открыть все реальные страницы в браузере. Проверить начало игры, управление, заметное изменение состояния и ошибки консоли; не ограничиваться наличием canvas или успешной сборкой.
6. Сетевые CDN-зависимости зафиксировать явно. CDN не входит в перенесённые исходники; автономность проверять отдельно. Не обещать offline-работу, если необходимые библиотеки ещё загружаются из сети.
7. Публикация под вложенным URL требует корректных путей ресурсов: проверить свежую сборку в том каталоге, где она будет размещена. Не менять оригинальный код ради предполагаемой оболочки в задаче переноса.
8. Сначала обыграть запуск, выгрузку и переходы на уровне общей оболочки; не рассчитывать на неподтверждённый API внутри сборок и не править минифицированную игровую логику. После выбора архитектуры проверить возврат в лабораторию, паузу, звук, мышь, перезапуск и выгрузку старого мира. Один работающий модуль не доказывает интеграцию остальных.

## Вступление LATENTPUNK

- Запуск: основное меню `scenes/start.tscn` → `scenes/prologue.tscn` → уже построенный экземпляр `scenes/intro.tscn`. Старый технический стенд `scenes/main.tscn` сохранён, но не является игровым стартом. Рестарт внутри города перезапускает только город, без повторения пролога.
- Пролог: `scripts/intro/prologue.gd`, логотип участника `assets/textures/nksv_logo.svg` на фоне `#141413`, без служебных подписей и кнопок. Любое нажатие показывает ненавязчивую подсказку Enter без плашки; удержание 1,2 с заполняет круг и пропускает вступление, отпускание и потеря фокуса сбрасывают удержание. Субтитры в Open Runde накапливаются по фактическим речевым таймкодам в блоки до четырёх строк; следующий блок начинается при переполнении.
- Речь: AudioStreamPlaylist последовательно проигрывает `assets/audio/prologue/narration.ogg` (74,12 с с эффектами) и `arrival_dry.ogg` (финальные 4,48 с без эффектов), без перекрытия и повторения. Общие часы 78,6 с и 38 фраз в `scripts/intro/prologue_cues.gd` сохранены. STREAM-плеер синхронизирует текст с аудио даже при отключённом звуке. Логотип сопровождает `logo_impact.ogg`; в последние 17 с открывается город и появляется амбиент. Город не рисуется под непрозрачной заставкой; после перехода восстанавливаются HUD, управление и маршрутизация звука. Происхождение и рецепт обработки — `assets/audio/prologue/provenance.json`; исходный MP3 удалён по просьбе участника после проверки.
- Маршрут: остановка → торговая улица → поворот направо на перекрёстке → площадь → LATENT SYSTEMS, Центральный проспект, 18 → холл → разговор с администратором → вызов лифта → самостоятельный вход → выбор 14-го этажа → кабинет 1406 → компьютер. Вход и выход из здания срабатывают при проходе через дверь. Уличный путь около 340 м; скорость 3,8 м/с. WASD, мышь, E; Esc открывает паузу с повторным запуском и возвратом в меню. Выбор другого этажа оставляет игрока в холле и вызывает короткую реплику.
- Архитектура, транспорт и мебель генерируются в `scripts/intro/city.gd` и `interiors.gd`. `geometry.gd` повторно использует меши и объединяет экземпляры по форме, материалу и пространственным участкам 48 м. Масштаб применяется в локальных осях **до** поворота (`scaled_local`), иначе фасады и машины растягиваются в неверных направлениях. Кафе и велопарковка разведены; колёса — открытые объёмные ободы со спицами. Вход башни имеет непрозрачные простенки и замкнутый тамбур, шахта лифта продолжается до потолка холла.
- Стены холла: непрозрачные бетонные и кремовые секции ограничивают отдельные окна с материалом `glass`; прежние сплошные панели `clear_glass` показывали небо из-за отсутствия внешнего окружения у отдельной сцены холла. Сохранены колонны, центральный дверной проём шириной 4 м, ресепшен и лифт.
- У двух движущихся машин шины, диски и крепёж вращаются вместе вокруг четырёх отдельных осей. Угол рассчитан по пройденному расстоянию и радиусу шины 0,43 м; перенос на начало маршрута не добавляет вращение. Припаркованные машины остаются статическими. Регрессия направления, скорости, остановки и переноса: `Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script tests/intro_traffic.gd`.
- Автобус у остановки имеет двухстворчатую дверь только со стороны тротуара, перед передним колесом. Дверная рама прилегает к кузову; верх остекления выровнен с окнами. Соседнее переднее окно сужено, чтобы не пересекаться с дверным блоком.
- Покрытие дворика кафе (`x=20..54`, `z=62..100`) и дорожка позади него имеют общую высоту, но не перекрываются: дорожка разделена на два прямоугольника вдоль границ дворика. Это устраняет z-fighting без ступеньки на маршруте.
- Необязательные городские взаимодействия: водитель у автобуса, два собеседника у кафе, парные кнопки перехода `(29.5, -69)` / `(29.5, -91)` и рекламный стенд на площади `(155, -68)`. `CROSSING_APPROACHES` задаёт противоположные тротуары и ориентацию: сигналы смотрят вдоль зебры на противоположный подход, кнопки — на свой тротуар. Корпус кнопки уменьшен с 1,50×1,90×0,28 до 0,56×0,88×0,14 м, с козырьком, небольшим дисплеем и индикатором. Точка взаимодействия вычисляется из позиции реальной кнопки. Обе панели показывают общий запрос и сбрасываются через 12 секунд; анимируется только нажатая кнопка. Светофор не меняет движение транспорта и не гарантирует безопасный переход. Подсказка E появляется только в пределах 3,1 м при взгляде; через препятствия взаимодействовать нельзя. Разговоры не блокируют управление, останавливаются на паузе и обрываются при удалении дальше 5 м или смене локации. У кафе три варианта беседы; стенд переключает четыре слогана. Физические дисплеи работают независимо от субтитров, звуки соблюдают настройку звука. Состояние хранит `scripts/intro/street_extras.gd`; регрессия — `tests/intro_street.gd`.
- Визуальный стиль по выбору участника — белое графичное ретро, не пастельный псевдореализм: белые фасады и интерьеры, фирменные AC2954 / 5B4CFF, сливовый асфальт 211F2D, лиловое окружение и цветные тени. Палитра — `Geometry.COLORS`; цвета кожи/волос и одежды NPC согласованы отдельно. Свет нейтрально-белый, ambient лиловый, туман ослаблен. `assets/shaders/intro_surface.gdshader` использует `diffuse_toon` без спекуляра; его разделяют геометрия и NPC. Вместо шумного асфальта, древесных волокон и блеска металла оставлены плоские цветовые массы, крупные швы и очень слабая печатная фактура штукатурки. Контуры создаются существующими тёмными рамами и деталями, без дополнительного прохода обводки. Прозрачное `clear_glass` сохранено отдельно. Четыре каскада теней покрывают 240 м.
- Население: общий уличный бюджет 64 перераспределён в 50 прохожих, 12 сидящих гостей кафе у старта и двух официантов; три участника необязательных взаимодействий сохранены отдельно. В холле 18, на этаже 6 и отдельный администратор. `city.cafe_seats` привязаны к реальным креслам шести столиков; поза строится суставами с бёдрами на высоте сиденья, согнутыми коленями и обувью у пола, без погружения стоящей модели. Официанты в светлых рубашках с тёмными фартуками идут по `cafe_staff_routes`, задерживаясь 2–3,2 с у точек `cafe_staff_stops`; сохранены обход мебели и разделение с соседями. Все 64 модели используют те же шесть MultiMesh-групп. Симуляция 20 Гц, интерполяция поз, отсечение после 125 м; NPC без физической коллизии. Пауза города выключает его обработку и возобновляет её при возврате. Зависание на остатке отступления менее миллиметра исправлено; регрессия — `tests/intro_pedestrians.gd`.
- Экранное оформление: `assets/shaders/intro_tape.gdshader` переделан под аналоговый VHS вместо квадратного шума/муарной сетки. Яркость и цвет разделены в YIQ: цветовой канал растекается по горизонтали и запаздывает, RGB расходятся на контрастных краях. Нерегулярное смещение строк, медленная tracking-полоса и нижняя head-switch-зона дают кассетную нестабильность без регулярных клеток. Зерно берётся из `assets/textures/intro/tape_noise.png` двумя неосевыми выборками, без `floor(pixel/3)` и синусного float-хеша. Один проход, без дополнительного LUT. Один и тот же фильтр с полной силой включён в городе, главном меню и заставке с логотипом; файл логотипа не изменён. Городской HUD остаётся над фильтром, экранные накладки не перехватывают мышь. Прежние параметры муара и ослабление эффекта на заставке удалены.
- Компьютер открывает `scenes/interview.tscn` как слой над живым Intro; устаревшая регистрация и сигнал `interview_requested` удалены. В `scripts/interview/`: `questions.gd` — десять вопросов, `progress.gd` — ответы и результаты только в памяти текущего прохождения, `interview.gd` — экран и фазы, `assessment.gd` — два коротких задания с фотографиями после 02 и 06. Новый запуск всегда начинается с первого вопроса, старые файлы прогресса игнорируются. Восемь предоставленных кадров переименованы по содержимому в `assets/textures/interview/`; десять слотов сцены меняются независимо. Один CRT-проход с заметными RGB-краями и защитой текста; один короткий силуэт в окне после последнего ответа. Каретка — реальная запись CC0, музыка Long note One — CC BY 4.0, титры в паузе. Ответ/пропуск, уход от NPC, переход и рестарт отменяют старую речь. Пауза и потеря фокуса замораживают плеер и часы; mute меняет только громкость. Фоновый звук интервью приглушается под речь. Финальный возврат в кабинет ждёт заключительную запись.

## Четыре платформы и GitHub Release

- Каноническая версия релиза — `application/config/version` в `project.godot`, сейчас `0.2.0-alpha`. Числовые поля macOS в `export_presets.cfg` сейчас `0.2.0`, для следующего релиза обновляются вместе с версией проекта.
- Пресеты: `Web` — Compatibility без потоков, `Linux` — x86_64, `Windows` (платформа Windows Desktop) — x86_64, `macOS` — universal. Для ARM64 включены импорт ETC2/ASTC в проекте и этот формат в macOS-пресете; без него Godot отклоняет universal-экспорт. macOS не подписана/не нотарифицирована; Windows не подписан, модификация PE-ресурсов отключена для экспорта на Linux без rcedit.
- Упаковщик `.github/scripts/export_release.py` импортирует проект, экспортирует все четыре пресета во временные каталоги, создаёт ZIP с инструкциями и уведомлениями об авторстве, затем `SHA256SUMS`. Готовый macOS ZIP не перепаковывается: сохраняются права и структура app bundle. Выход — `build/release/<версия>/`, каталог игнорируется git.
- `.github/workflows/release.yml` запускается по push в `main` или вручную. Скачивает официальный Godot 4.7.2 Standard и только необходимые release-шаблоны, выполняет упаковщик и существующие `tests/smoke.gd`, `tests/interview.gd`. После успешного экспорта публикует prerelease `v<версия>` с четырьмя ZIP и контрольными суммами. Текст — [RELEASE_NOTES.md](RELEASE_NOTES.md).
- Опубликованная версия неизменяема: следующий push с тем же `config/version` пропускает выпуск. Черновик допускает повтор на том же коммите; чужой черновик или тег требуют новой версии. Публикации сериализованы, а состояние черновика повторно проверяется перед загрузкой файлов.
- У GitHub job публикации есть `contents: write`; остальные job только читают. Используется автоматический `GITHUB_TOKEN`. Публикация удалённого релиза требует push участника и разрешённых Actions в настройках GitHub.
- Эти сборки содержат текущее вступление и собеседование, не планируемую кампанию. Самостоятельные `games/` не добавляются в экспорт Godot до реализации и проверки общей оболочки.
- Headless-регрессия `tests/smoke.gd` теперь задаёт горизонтальный viewport до создания сцен, вместо зависимости от размера dummy-окна. Удалены проверки наличия скриптов и точного числа декоративных маркеров; проверки ориентации, переходов состояния, детерминизма генерации и повторного использования пула сохранены. `SMOKE_OK` и полная `INTERVIEW_PASS` получены на Godot 4.7.2.
- Проверка релиза на текущей машине: все четыре ZIP собраны упаковщиком; проверены CRC, `SHA256SUMS`, notices, права исполняемых файлов и обе архитектуры macOS. Распакованная Linux-сборка стартовала headless. Реальная распакованная Web-сборка прошла меню → пролог → удержание Enter → город → движение → пауза → возврат в меню → повторный запуск и движение без JavaScript-ошибок. После исправления свежий экспорт выдержал переход, движение и повторный запуск; исходники/готовые сборки самостоятельных мини-игр не менялись.

Локально выполнены 11 сценариев состояния релиза и реальная read-only проверка GitHub API на публичном `godotengine/godot-builds`: отсутствующий тег разрешил новый выпуск без обращения к `/commits`. Оба workflow прошли actionlint. Полная публикация в репозитории участника требует нового commit/push с исправленным workflow; повтор старого run использует старый код.
