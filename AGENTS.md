# Работа одного участника с агентами

Главный участник принимает решения о механике, стиле и приоритетах. Агенты получают ограниченные задачи с ожидаемым результатом. Один агент отвечает за один участок кода или ресурсов в конкретный момент. Изменения принимаются после запуска игры и веб-проверки.

## Роли

| Роль | Задача | Проверяемый результат |
| --- | --- | --- |
| Архитектор | Предложить минимальный вертикальный срез и границы файлов | Список сцен, сигналов и зависимостей на одной странице |
| Программист | Реализовать одну механику или один экран | Игра запускается, описаны входы и выходы |
| Художник-помощник | Подготовить запросы и отобрать ресурсы после темы | Исходники, экспорт, учёт происхождения |
| Проверяющий | Пройти один сценарий в браузере | Шаги воспроизведения и серьёзность ошибок |

## Контракт задачи агенту

Передавайте: цель игрока, текущую рабочую сцену, конкретные файлы, ограничение времени, критерии приёмки и запрет менять соседние модули без согласования. Просите агента перечислить изменённые файлы и способ проверки. Для сложной задачи сначала получите короткий план с архитектурным решением, затем реализацию. При конфликте предложений выбирайте вариант, который быстрее даёт работающий игровой цикл.

Пример: `Добавь один тип взаимодействия в scenes/game/main.tscn и scripts/game/. Управление уже задано в InputManager. Критерий: игрок видит цель, действие даёт мгновенный отклик, проект запускается в Godot 4.7.2 и веб-экспорте. Не меняй технический стенд и экспортные настройки. Сообщи файлы и способ проверки.`

## Правила проекта

- Движок: Godot 4.7.2 Standard, GDScript, режим Compatibility, однопоточный веб-экспорт.
- До объявления темы не добавлять игровые уровни, персонажей, сюжет, тематические звуки или готовый игровой цикл.
- После темы сперва сделать вертикальный срез: цель, действие, обратная связь, итог. Затем наращивать содержание.
- Не ставить дополнения и зависимости без конкретной необходимости. Файлы добавлять по назначению, не создавать пустые подсистемы.
- Сохранить запускаемую основную ветку. Агентам не поручать параллельные изменения одного и того же файла.
- Перед принятием изменений выполнить импорт проекта, запуск и проверку свежего веб-экспорта.
- Исправлять ошибки, замеченные при проверке, до следующей партии задач.
